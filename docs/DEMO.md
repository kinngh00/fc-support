# FC-SUPPORT 3분 데모 가이드

## 0:00–0:25 · 문제와 제품

첫 화면에서 다음을 설명합니다.

> FC 온라인 감독모드 상위 10,000명의 실제 선발 데이터를 매시간 수집해 선수 픽률과 랭킹 변화를 빠르게 조회하는 서비스입니다. 검색할 때마다 외부 API를 호출하지 않고 검증된 DB 스냅샷을 제공합니다.

확인할 화면: 선수 픽률 조회의 랭킹 범위, 팀컬러, 상세 포지션 조건.

## 0:25–0:55 · 실제 데이터 분석

1. 랭킹 범위를 지정합니다.
2. 팀컬러를 검색해 선택합니다.
3. 픽률 조회를 실행합니다.
4. 같은 선수라도 시즌과 강화단계가 다르면 분리되고, 분모가 해당 포지션 전체 사용 수라는 점을 설명합니다.

강조할 점: 더미 데이터나 임의 보정값을 사용하지 않습니다.

## 0:55–1:25 · 랭커와 이력

1. 감독모드 랭킹 페이지를 넘깁니다.
2. 구단주를 검색합니다.
3. 순위·구단가치·승률의 1시간봉/일봉/주봉을 확인합니다.
4. 선발 스쿼드, 포메이션, 팀컬러와 최근 경기를 확인합니다.

강조할 점: 포메이션은 랭킹 문자열이 아니라 최신 매치의 실제 포지션 코드로 계산합니다.

## 1:25–1:50 · 커뮤니티와 인증

1. 비로그인 상태에서도 게시글과 댓글을 읽습니다.
2. 회원가입 또는 로그인 후 게시글과 댓글을 작성합니다.
3. 다른 회원의 글은 삭제할 수 없고 작성자 본인만 삭제할 수 있음을 설명합니다.

강조할 점: `scrypt`, HttpOnly 세션, 서버 작성자 권한 검사를 사용합니다.

## 1:50–2:25 · 데이터 안정성

아키텍처 문서의 수집 파이프라인을 보여주며 설명합니다.

> 새 수집은 building 상태에서 별도로 진행됩니다. 10,000명 수집과 저장이 끝났을 때만 하나의 트랜잭션으로 active를 교체합니다. 중간에 서버가 재시작되거나 API가 실패하면 기존 데이터가 계속 제공됩니다.

확인할 자료: [ARCHITECTURE.md](./ARCHITECTURE.md)의 파이프라인과 ERD.

## 2:25–2:50 · AI-Native 개발 방식

사이트의 AI-Native 소개 영역과 검증 기록을 보여줍니다.

> AI로 구현 속도를 높였지만 API가 제공하지 않는 값을 만들지 않았습니다. 원본 응답, DB, 자동 테스트와 화면 캡처로 결과를 확인하고, 발견한 오류는 테스트와 작업 규칙으로 고정했습니다.

확인할 자료: [AI_NATIVE_DEVELOPMENT.md](./AI_NATIVE_DEVELOPMENT.md).

## 2:50–3:00 · 마무리

> 이 프로젝트는 AI 사용 경험만 보여주는 데모가 아니라 데이터 수집, 제품 설계, 검증, 보안과 배포까지 연결한 실제 동작하는 풀스택 결과물입니다.
